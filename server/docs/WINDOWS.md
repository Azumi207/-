# 帧语团队服务端 0.1.0（对应 Windows 客户端 0.2.0）

这是可自行部署、可供不同字幕组各自使用的第一版服务端。**一个部署实例对应一个字幕组**，不是已经上线的公共平台。成员不需要安装服务端，只需 Windows 客户端和管理员提供的服务器地址、账号。

## 最简单：先在 Windows 本机试用

1. 安装 Python **3.12 或更新版本**（推荐先用已测试的 3.12）。将服务端 ZIP 解压到自己有写权限的固定文件夹。不要在 ZIP 内运行，不需要管理员身份。
2. 双击 `start.cmd`。首次会联网安装锁定的 Python 依赖到此文件夹的 `.venv`，然后要求设置 `admin` 的密码（至少 12 字符，输入时不会显示）。后续启动不会重置密码。
3. 保持该终端运行。默认地址是 **http://127.0.0.1:8765**，只能这台电脑访问；Ctrl+C 停止。关闭窗口会停止服务器，但不会删数据。
4. 启动新版帧语：**团队 → 登录服务器 / 项目大厅…**，输入上述地址与管理员账号。
5. 展开“项目管理”：创建成员账号，新建项目，选中项目后分别分配 `source`（片源）、`translator`（初翻/打轴）、`reviewer`（校对）或 `encoder`（压制）。一个账号在同一项目中有一个角色，不同项目可不同。管理员可代办，但不能校对通过自己提交的初翻。
6. 片源成员登录，选择项目，在下方展开区点“上传片源”。上传前请确认服务器地址和所选文件；这是显式上传，不会扫描或自动上传其他素材。

第一次安装需要联网。后续依赖没有改变时可直接启动。不要把 `.venv` 从 Windows 复制到 Linux；在目标系统重新安装。

## 字幕组日常操作

| 成员 | 软件中的操作 | 结果 |
|---|---|---|
| 片源 | 上传视频（支持中断后续传） | 视频 SHA256 校验通过后，项目进入“初翻待领取” |
| 初翻 | 领取当前阶段 → 下载最新为新副本并编辑 | 自动打开本地视频和工作字幕，可离线打轴、翻译 |
| 初翻 | 再次打开团队大厅 → 同步当前字幕草稿 | 创建不可覆盖的字幕版本，仍归自己处理 |
| 初翻 | 完成初翻 · 交给校对 | 进入“校对待领取”，释放领取人 |
| 校对 | 领取 → 下载 → 在原编辑器校对 | 视频、ASS 样式、说话人和时间轴保持原来的工作方式 |
| 校对 | 填写原因 → 校对退回 | 先同步当前修改，再退回“初翻待领取”；版本和意见留下记录 |
| 初翻 | 重新领取 → 下载最新新副本 → 修改 → 再提交 | 不覆盖之前的离线草稿 |
| 校对 | 校对通过 | 先同步当前修改，再锁定通过的具体版本，进入“待压制” |

“校对通过”**不会自动执行压制、上传成片或发布**。压制成员可下载通过后的字幕和片源，使用客户端现有显卡压制功能。服务器自动压制/发布不是本次实现范围。

### 文件、断线与版本冲突

- 本地缓存与工作文件位于 `%LOCALAPPDATA%\Frameflow\Team`，按服务器、账号、项目隔离。每次“下载最新”创建新工作副本；“继续本地草稿”重新打开该账号最近的本地副本。
- 字幕旁的 `.team.json` 保存项目和基版本，不含密码、令牌。离线编辑时保留它；也可从“最近打开”打开工作字幕，联网登录原账号后提交。把文件移走或另存为别处不会自动转移团队关联；用“继续本地草稿”回到已关联副本再合并。
- 上传前先在本地保存当前字幕。服务器同时检查项目修订号、领取人和字幕基版本。冲突时拒绝覆盖，需下载最新副本人工比较合并；**没有自动合并，也没有多人同时编辑同一字幕**。
- 网络中断时可能出现“服务器已提交，但客户端还没收到回执”。先刷新大厅和版本记录，不要盲目重复提交。若本地基版本落后，保留原文件，下载新副本再比较。
- 视频按 4 MiB 分块上传，取消/断线后再次选同一个片源可继续。下载支持 Range 续传，完成后验证大小及 SHA256。上传任务 24 小时无活动后过期。片源提交后固定不变；要更换片源请新建项目，避免旧时间轴错位。
- 可释放自己搁置的任务；管理员可代为释放。历史字幕版本不覆盖；当前大厅显示最近 8 个版本和最近 5 条交接摘要，API 保留全部版本和最近 100 条事件。
- 服务端保存原始 UTF-8 ASS/SSA 文本，不转 SRT、不剥离样式/说话人/覆盖标签。本版只交接字幕文件和项目级意见，**不上传逐行校对 sidecar、外置字体、自动化 Lua 或成片**。压制电脑仍需相同字体，否则无法保证跨机器显示一致。字体和其他附件管理留待后续。

## 让其他电脑连接（公网必须先配置 HTTPS）

默认只监听回环地址，是故意的保护措施，**不能把 127.0.0.1 发给其他成员作为公共地址**。公网部署需要一台常在线服务器、域名及管理员维护 HTTPS。应用服务仍建议监听 `127.0.0.1:8765`，由同机反向代理转发。

例如已安装并正确配置域名与证书的 Caddy 可使用以下配置模板（`HOST` 必须换成真实域名）：

```caddyfile
HOST {
    reverse_proxy 127.0.0.1:8765
}
```

成员填写 `https://你的域名`。反向代理必须保留 Authorization、Range、If-Range、Upload-Offset 等请求头，允许至少 8 MiB 请求体（JSON 字幕上限）和 4 MiB 上传分块，允许较大的流式响应。不要把 `data` 文件夹配置成静态网站目录，不要在日志中记录 Authorization 或请求体。当前版本不信任转发 IP 头；经过代理的登录将共享每 IP 30 次/分钟的限制，适合小组而非大型开放注册服务。

部署模板参考 [Caddy 反向代理官方文档](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy) 和 [HTTPS 条件说明](https://caddyserver.com/docs/automatic-https)。这里只提供配置模板，未替你配置域名或验证公网部署。

仅在可信内网测试时可以显式打开 HTTP：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -Bind 0.0.0.0 -AllowInsecureHttp
```

需要自行设置防火墙、使用服务器实际内网 IP，客户端也要明确勾选 HTTP 风险确认。**HTTP 传输密码、令牌和素材不加密，不应用于公网。** 本软件不会自动开端口、配置防火墙、注册域名或把服务器发布到互联网。

## Linux 启动

准备 Python 3.12+ 与对应的 `venv` 支持，然后在解压目录运行：

```sh
chmod +x start.sh
./start.sh
```

Windows 脚本与服务端已在本机实测；Linux 脚本提供相同启动逻辑，尚未做 Linux 实机部署验证。建议以普通专用账号运行，生产环境由管理员配置进程管理器；不要以 root 运行应用服务。单实例、单 worker，不能让多台服务器共享同一个 SQLite 数据目录。

## 自定义路径和限额

建议正式部署把数据放在独立、固定目录。Windows：

```powershell
.\start.ps1 -Data D:\FrameflowTeamData
```

Linux 可用 `FRAMEFLOW_TEAM_DATA=/srv/frameflow-data ./start.sh`。升级时保留数据，替换程序，不要用新空目录误认为历史丢失。默认单个视频最多 20 GiB，已提交视频加有效上传预留量总共 100 GiB；字幕单次 UTF-8 正文最多 4 MiB，JSON 请求体最多 8 MiB。限额是视频配额，不是操作系统磁盘硬配额；数据库历史、备份和过期临时上传也占空间，需要维护磁盘。

手动启动以调整限额（先完成初始化）：

```powershell
.\.venv\Scripts\python.exe server.py --data D:\FrameflowTeamData serve --port 8765 --max-video-gb 40 --quota-gb 300
```

## 管理、备份与恢复

以下命令使用安装目录的 Python；Linux 替换成 `.venv/bin/python`。路径示例需要按实际部署修改。

```powershell
# 重置成员密码，立即吊销其原登录会话（密码交互输入，不出现在命令行）
.\.venv\Scripts\python.exe server.py --data D:\FrameflowTeamData reset-password translator
# 禁用离组成员；可由管理员在客户端释放其未完成任务
.\.venv\Scripts\python.exe server.py --data D:\FrameflowTeamData disable-user translator
# 备份到一个尚不存在的目录；不要放在 data 内
.\.venv\Scripts\python.exe server.py --data D:\FrameflowTeamData backup D:\Backups\frameflow-20261019
# 停服后清理 24 小时过期的未完成上传，不删已提交视频和字幕
.\.venv\Scripts\python.exe server.py --data D:\FrameflowTeamData cleanup-uploads
```

备份使用 SQLite 一致快照，并复制快照引用的不可变视频文件。出现 `BACKUP_COMPLETE.txt` 才算成功；失败目录不要用于恢复。备份中的登录会话已清空，未完成上传不包含在内。备份也含私有素材和密码哈希，需妥善限制权限。

**恢复**：停服 → 保留旧数据目录作为应急副本 → 将完成的备份目录复制为新的数据目录 → 用 `--data` 指向新目录启动 → 重新登录并检查项目、通过版本和视频。不要直接覆盖运行中的 SQLite 文件。本次已验证备份恢复后原令牌失效、重新登录可读取通过版本和完整视频。

## 安全边界与当前限制

无默认密码、无开放注册；管理员创建成员并分配项目角色。密码使用 Argon2id，服务端只存登录令牌 SHA256；会话 8 小时到期，退出/禁用/重置会撤销会话。项目、字幕、视频、上传分块均在服务端检查权限；文件 ID 是服务端生成的值，文件名不用于拼接存储路径。禁止自己审批自己提交的初翻。所有 SQL 业务参数使用参数绑定。

这是小型字幕组测试版，不代表已经通过独立安全审计或大规模压力测试。当前没有邮件找回、MFA、公共注册、多租户后台、跨区域对象存储、聊天通知、自动版本合并、服务器压制队列与平台发布。服务器管理员能读取本组数据；不是端到端加密存储。只上传字幕组有权处理、分享的素材。
