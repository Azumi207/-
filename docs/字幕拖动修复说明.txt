字幕位置拖动修复 · 2026-10-20 · 本地修复版（GitHub 尚未更新）

修复现象：精确 ASS 模式下，拖动时只有选框移动、字幕本体停住，松手后字幕先消失再出现。

本次调整：
1. 拖动过程中持续按最新坐标请求真实 libass 帧，不再等到松手才更新。
2. 新帧未完成时保留上一帧，松手后直接替换，不先清空字幕画面。
3. 单条可见且不含固定遮罩/旋转原点/变换等复杂定位的字幕，先平移现有真实字幕位图提供即时反馈，再用新的 libass 帧校正。
4. 多条同时显示、遮罩或复杂变换不平移整张字幕图，而是刷新完整场景，避免把其他字幕或固定遮罩一起拖走。这类场景的响应速度取决于实际渲染耗时，不承诺零延迟。
5. 精确模式开始拖动时暂停播放，固定当前编辑帧。已有 move 动态定位行仍按原规则禁止直接拖动。
6. 鼠标捕获丢失（如切换窗口）也正常结束拖动；一次拖动保持一个撤销步骤，支持撤销/重做。

测试：使用真实 WPF 窗口、libass 输出像素，检查普通字幕、多字幕、矩形遮罩和全屏拖动；同时核对松手后无空白帧、非目标字幕不移动、撤销与重做。
测试入口在 tests/drag/ 中。Windows 开发环境安装 .NET 9 SDK 并准备 FFmpeg 后，可构建 DragProbe.csproj，然后运行：
dotnet DragProbe.dll APP_DIRECTORY/Frameflow.dll tests/drag/drag.ass OUTPUT_DIRECTORY
输出 drag-behavior.json 和实际预览截图。探针自身退出 0 表示完成观测，修复验收还须检查 JSON 的 all_fixed=true；旧版和回滚版本用于复现 all_fixed=false。

此修改不改变字幕格式或压制参数；旧版源码、程序和已发布附件保持不变。请用新文件夹试用，不要覆盖旧版。

补充：以上为上一轮 .NET 9 修复记录；当前源码已迁移 .NET 10 LTS，请使用 .NET 10 SDK 构建测试。
